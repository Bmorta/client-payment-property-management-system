# Contract configuration, schedule printing, commission terms, map controls and receipt search

## Completed

1. Contract monitoring monthly installments populate from selling price less agreed DP divided by term, rounded up to centavos so a final balanced installment preserves the exact principal. The amount remains editable. Manual values are labeled and survive basis changes; Reset to Computed Amount restores automatic updates. A manually differing schedule requires explicit final-installment balancing acknowledgement, and the existing backend still rejects a schedule that cannot cover the original contract price over the chosen term. Agreement edits retain their existing admin permissions, reason and history.
2. Each client-property account has Print Payment Schedule. The Client List has Print Multiple Client Schedules with account-level checkboxes, name/ID/project/property search, Select All/Clear All, pagination and preview. Selections are deduplicated and capped at 100 accounts / 10,000 schedule rows per batch. Preview shows one selected account at a time; print includes all selected accounts. Each account starts on a new page. Output uses 8.5 × 13-inch portrait long bond paper, client/contact/address/property/contract details, original DP basis, received/paid/outstanding totals and the complete authoritative allocation-backed schedule. Latest effective allocation dates are used. Compact schedules over 36 rows use two table panels; schedules over 72 rows require readable continuation mode. No rows are clipped or omitted by fixed-height containers. A continuation option is also available for any schedule.
3. Commission suggestions: terms ≤12 use the buyer term, 13–47 suggest 24, and ≥48 suggest 30. New assignments default to the suggestion; saved terms remain Custom until explicitly changed. Draft per-agent schedules can be inspected before review. A shorter unused agreement previews and confirms the unused rows removed, redistributing only the unearned agreement budget. Term changes that would redistribute allocation-linked or historical monthly commissions are blocked for administrator review rather than rewriting them. This is intentionally conservative; there is no override that deletes financial history. Individual/bulk removal applies only to unused zero-budget entries, with a reason, confirmation, version checks and agreement/audit history. Allocated rows must use the term editor rather than arbitrary row deletion.
4. Select Buyer is a searchable, interactive input; it searches existing clients through the current client-search API. Associated account selection remains buyer-scoped. The backend rejects a mismatching supplied buyer ID. Already-assigned sale protections remain unchanged.
5. Project Map now has Edit Map / Replace Image, a pending-image preview, Save/Confirm and Cancel. Delete Map requires confirmation and current map version. It removes only that project's managed image bytes, retaining a metadata tombstone and audit history; projects and lots remain unchanged. Upload is available again after deletion, with version-safe re-upload. The existing viewer and PNG/JPEG limits are preserved.
6. Payment Transactions has a dedicated Receipt Number text filter for full/partial, case-insensitive matching. Leading zeros remain text. Search runs over all matching records and combines with general search, date, payment method, client, project and status filters. Pagination resets when it changes, and totals/printing/CSV/Excel use the active receipt filter. General transaction search also continues matching receipt numbers.
